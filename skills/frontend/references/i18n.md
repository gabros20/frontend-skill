# Internationalization

Purpose: canonical home for i18n implementation mechanics: logical properties, `Intl` APIs,
`lang`/`dir` attributes, and text-expansion resilience.

Read when:
- Building layout that must survive RTL, a longer translated string, or locale-correct
  date/number/plural formatting.
- Writing directional icons, `lang`/`dir` attributes, or CSS that should not need a separate RTL
  stylesheet.

Skip when:
- Input types/autocomplete for form fields: use `forms.md` (this file only owns the
  composition-input i18n-correctness edge case below).
- Content/copy voice and tone: use design.

Inputs: the locales the product must support and its existing i18n library, if any.

Produces: layout and markup that hold up under translation and RTL without a parallel stylesheet or
duplicated logic.

## `lang` and `dir`

Set `lang` with a valid BCP 47 tag; a mismatched `lang`/document-language pair is a real, checkable
defect (`html-xml-lang-mismatch`), not a style nit. Use `dir="auto"` for user-generated content whose
script is not known ahead of time; use explicit `dir="rtl"`/`dir="ltr"` when the surface's language
is known and fixed.

## CSS logical properties

Replace every physical-direction property with its logical equivalent so RTL and vertical writing
modes work without a parallel stylesheet:

| Physical | Logical |
|---|---|
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `padding-top` / `padding-bottom` | `padding-block-start` / `padding-block-end` |
| `left` / `right` (positioned) | `inset-inline-start` / `inset-inline-end` |
| `border-right` | `border-inline-end` |
| `text-align: left/right` | `text-align: start/end` |

Flex/grid direction auto-reverses under RTL once logical properties are used consistently; no
`[dir="rtl"]` override is needed for layout. Directional icons still need an explicit flip:
`[dir="rtl"] .arrow { transform: scaleX(-1); }` for icons that convey direction (arrows, chevrons).
Icons that do not convey direction (a play button) must not be mirrored.

## `Intl` APIs and pluralization

Use `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.RelativeTimeFormat`, and `Intl.ListFormat`
instead of hand-rolled locale formatting for dates, currency, relative times, and lists. Never
concatenate a raw count into a string (`"You have " + count + " items"`); plural rules vary far
beyond a singular/plural binary (English has 2 forms, Russian 3, Arabic 6). Use `Intl.PluralRules`
or an ICU-based library (`react-intl`, `i18next`) so every CLDR plural category for the target
locale is covered.

## Text-expansion resilience

Canonical home for this fact: reserve roughly 30 to 40% extra space for translated text. German and
Finnish commonly run that much longer than English for the same content. Never build a fixed-width
text container, and test layouts with the longest target language, not just English. This affects
component and form layout directly; `forms.md` and `state-completeness.md` should cite this rather
than restate the percentage.

## Grapheme-safe truncation

Naive `str.slice(0, n)` or a check against `str.length` assumes one visible character equals one
UTF-16 code unit, which breaks on emoji, combining marks, and any grapheme spanning multiple code
points — it can split an emoji sequence mid-cluster and corrupt the rendered glyph. Use
`Intl.Segmenter` instead:

```js
function truncateGraphemes(str, maxGraphemes) {
  const segmenter = new Intl.Segmenter('en', { granularity: 'grapheme' });
  const segments = [...segmenter.segment(str)];
  return segments.slice(0, maxGraphemes).map(s => s.segment).join('');
}
```

`granularity` also accepts `'word'` and `'sentence'` for locale-aware boundary truncation, which
handles CJK text (no spaces) correctly where a naive space-split does not. Supported in all modern
evergreen browsers and Node.js 16+; verify current support (per the perishable-support rule) before
relying on it without a polyfill.

## Mixed-direction runs and locale sorting

Wrap embedded runs of the opposite direction (a username or product code inside RTL prose) in
`<bdi>` or `unicode-bidi: isolate` so the surrounding text's directionality does not leak into or
get corrupted by the embedded run — plain `dir` attributes do not isolate. Sort user-facing lists
with `Intl.Collator` (locale-aware) instead of `Array.prototype.sort()`'s default code-point order,
which misorders accented and non-Latin characters.

## RTL testing and icon mirroring

Test with a real RTL locale rendered end to end, not just a mirrored stylesheet in isolation; logical
properties can be correct individually while a composed layout still reads wrong. Avoid baking text
into images: it cannot be translated, resized, or read by a screen reader.

## IME composition

CJK input methods compose a character over several keystrokes before committing it; a naive
"Enter submits the form" handler fires mid-composition and submits garbage. Guard submit-on-Enter
with the input event's `isComposing` state (or an equivalent composition-start/composition-end
check) so Enter only submits after composition finishes. This is a real, non-obvious
i18n-correctness bug class, not an edge case to skip.
