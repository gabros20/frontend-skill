Ask an agent to build a UI and you get a component that renders the happy path, skips the empty/error/loading states, mishandles tokens, and ships with no tests. frontend replaces that with a router: route to the primary job and the platform it targets, read the reference completely, then ship production code with the full state set, accessibility floors met, and the tests that guard it. How it routes

Not a fixed pipeline — a faceted router. Enter at whatever job you have: "fix Core Web Vitals on this page" jumps straight to performance; "wire this design handoff" jumps to tokens and states. Every route composes the smallest sufficient reference set — one primary job, at most one platform overlay, a web stack overlay only when it applies — and nothing unrelated is loaded.

primary job → platform overlay → stack overlay → code & tests → validate → handoff

The skill operates standalone — invoked alone it runs the full route; given a design handoff (handoff.yaml plus DESIGN.md) it implements that intent faithfully rather than silently overriding it.

identify the primary jobPick the one engineering job the request needs — state and data, state completeness, forms, accessibility, performance, client security, testing, i18n, or design-handoff-and-tokens. → SKILL.md
add the platform overlayWeb is the default substrate. Native (iOS, Android, React Native) overrides the web defaults when the platform is native — at most one platform overlay.
add a web stack overlay only when it appliesReact, Next.js, Tailwind, shadcn/ui — added only when the platform is web and the project names or uses that stack. An uncovered stack skips the overlay; the project's own conventions win.
read fully, then produceRead each selected reference completely, then ship production code with the full state set and exact values — tokens, thresholds, API names — not adjectives.
validate & hand offRun the dev-loop self-check — served build, screenshots at two viewports with reduced motion emulated, an interactive pass — then emit a compact handoff when downstream review or deployment is expected.
A green build is not a correct screen — the skill states what the dev-loop self-check surfaced and what remains, rather than presenting unrun tests or an unscreenshotted build as verified.

The non-negotiable laws

These universal invariants govern every reference — the load-bearing ones, condensed.

  • Project conventions winConform to the project's existing stack, structure, and idioms. Stack overlays sharpen core doctrine for covered stacks; for an uncovered stack, the core job ref plus the web-platform substrate carry the work.
  • Ship the full state set in codeDefault, hover, focus-visible, active, disabled, loading for every interactive element; empty, error, success for every data region. A build that renders only the happy path is incomplete, not done.
  • Reduced motion is a complete alternativeHonor prefers-reduced-motion (and each platform's equivalent) by swapping to a legible no-motion state, never leaving an element mid-transition.
  • Accessibility floors are constraintsMeet the contrast, target-size, focus, and keyboard floors from accessibility.md even when it is not open; cite its numbers, do not redefine them.
  • A green build is not a correct screenBefore claiming completion, run the dev-loop self-check: serve the build, screenshot every route at two viewports with reduced motion emulated, and interact with it.
  • Never present untested code as verifiedState what was run and what was not; if tests fail or a step was skipped, say so with the evidence rather than signing off.
  • Preserve design intent and product constraintsImplement a supplied design handoff faithfully; when code and a design, brand, or architecture constraint conflict, report it rather than silently override it.

Start here

Install once. It's a plain SKILL.md router — no flags, no config, no scripts — so it activates on natural-language phrasing ("build an accessible signup form", "implement a SwiftUI settings screen", "fix Core Web Vitals on this page", "wire this design handoff into React") rather than a fixed command.

# skills.sh ecosystem npx skills add gabros20/frontend-skill # clone + installer (per-host targets) git clone https://github.com/gabros20/frontend-skill && cd frontend-skill ./install.sh codex # or: claude | agents | cursor | antigravity | opencode | grok | hermes | all # use /frontend build an accessible Next.js signup form with every state and tests /frontend wire a design handoff into a React and Tailwind component with tokens
